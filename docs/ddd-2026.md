# DDD Perth 2026 booth kiosk (`/ddd-2026`)

The touch-screen app for the Perth AI booth at DDD Perth (Saturday 3 October 2026). The booth screen
and the tablets all open **perthai.org/ddd-2026**, so they share one Quokka Run leaderboard, and
organisers use it to walk visitors through the Perth AI spiel. Students can open the same link on
their phones to practise the game.

It's the one part of the site with a server side, and it's temporary. Take it down after the event
(see the end of this page).

## What's on it

- **Meet Perth AI:** the booth spiel as ten swipeable cards, from the Perth AI @ DDD 2026 deck. Who
  we are, why we exist, the three groups, what we run, what we care about, first time?, AI Disrupt,
  put your hand up, the volunteers and supporter, and QR codes to finish.
- **AI Disrupt 2026:** 2025 photos and stats, then four forms led by what 2026 needs most: sponsor,
  host the venue, speak or demo, and get notified.
- **Quokka Run:** a one-tap runner and the prize game. Jump hallucinations, GPU fires and 429s; at
  each gate, jump through for FACT or run under for HALLUCINATION. It speeds up every 20 seconds.
  Each player shows once on the board, at their best score. A player is their email if they gave
  one, so two different Sams get two entries; without an email, the name is all there is.
- **Forms:** join the Slack, what's on, suggest an event, offer a space, sponsor.
- **Admin** (hidden): hide players, clear the board, download the scores CSV, draw a random winner,
  and switch booth mode on or off for the device it's open on.

Every screen fits without scrolling on the booth screen and on iPad and Samsung tablets in either
orientation; only phones scroll.

## What's where

The app is plain HTML, CSS and JavaScript in `public/ddd-2026/`, served as-is. It isn't built by
Astro and uses its own copy of the brand tokens and fonts.

Some things to know before editing:

- **Game statements:** each has a `topic`, a `level` (1 easy, 2 medium, 3 hard), the `text`,
  whether it's a `fact`, and a `why` shown after answering. Statements sharing a topic never appear
  in the same run, so a true/false pair can't give each other away.
- **Keep it to one screen.** Adding a form field or more copy can tip a screen into scrolling on a
  tablet. Check it at 1024×768, 768×1024, 1180×820 and 800×1280. One-line form fields pair up two
  to a row.
- **Phones turned sideways** (844×390, down to ~340 tall with the browser bars) are wider than the
  phone breakpoint but far shorter than any tablet. They get their own `(orientation: landscape) and
  (max-height: 500px)` rules: slimmer buttons, a scrolling home screen, and the Quokka Run start
  button at the top of the right-hand column.
- **Paths:** the kiosk's own files are relative (`css/…`, `api/…`), because the app lives under
  `/ddd-2026/`. Images it shares with the rest of the site are the site's own files: the badge,
  mark, skyline, favicons and the 2025 photos in `public/summit/2025/`. Renaming or moving those
  breaks the kiosk too.
- **A new file the kiosk loads** goes in the `PRECACHE` list in `sw.js` too, so it's on the device
  before the wifi drops. (Anything missed is still stored the first time it's used.)
- **A new database column** goes in `ADDED_COLUMNS` in `src/lib/ddd2026.ts`, not only in the
  `CREATE TABLE`, or the live database never gets it.
- **Slack invite links expire** after 30 days (or 400 uses). Check `links.slack` is still live
  before the event.

## When the wifi drops

Nobody at the booth should have to do anything, and no visitor is told to find someone.

- **Sign-ups and scores are saved on the device first**, then sent. If the send fails, the visitor
  still gets their "thanks" or "Saved!" screen, and the device resends every minute, and as soon as
  it's back online, until it gets through. Requests give up after 8 seconds, so a flaky connection
  never leaves a button hanging.
- **A score is only ever counted once**, however many times it's resent: each run carries an id and
  the API ignores repeats. A run that waited out a drop-out keeps the time it was played (admin's
  "played" column) as well as when it arrived ("saved"). One played before the board was last
  cleared arrives hidden.
- **A device that reloads while offline still opens the kiosk.** The service worker (`sw.js`) keeps
  a copy on the device. It always tries the network first, so an online device runs the latest
  version; the copy is only used when the network fails or takes over 4 seconds. Leaderboards show
  the last one the device saw.
- **Admin shows what's waiting on the device it's open on**, sign-ups and scores separately. If
  anything is still waiting at the end of the day, get that device online before the week is out
  (see the limits below).
- **Switching the service worker off:** open the kiosk with `?sw=0` on that device, which removes it
  and its copy. To switch it off everywhere, replace `sw.js` with the one under "After the event"
  and deploy; each device drops it on its next load.

## What it collects

- **Sign-ups** go from the kiosk straight to Web3Forms, so they arrive in the same inbox as the
  site's own forms, with subjects starting "DDD Perth 2026 booth". Nothing is stored on our side.
- **Quokka Run scores**, in a Cloudflare D1 database (`perth-ai-ddd-2026`, bound as `DDD_2026_DB`):
  leaderboard name and score, plus an email for anyone who wants to be in the prize draw.
- **Anything waiting to send** (see above) sits in that device's browser storage, names and emails
  included, so it's bounded: anything still unsent after 7 days is dropped, each device keeps at most
  200 sign-ups and 200 scores, and each retry sends at most 10.

### Consent and the mailing list

Set up to follow the Spam Act 2003, which doesn't count a pre-ticked box as consent to marketing
email:

- Following up on what someone asked for (a Slack invite, a venue offer, telling the prize winner)
  needs no tickbox. Each form says so under the button.
- Event updates are a separate opt-in: an unticked "Send me Perth AI event updates too" box on the
  forms and on the prize-draw screen. "What's on" and AI Disrupt "Get notified" are themselves
  requests for updates, so they have no box. (`subscribe: true` in `forms.js`.)
- **Only add someone to a mailing list if they opted in:** `event_updates: Yes` in the sign-up
  email, or "event updates: yes" in admin's scores table (the `updates` column in the CSV).
  Every email you send them needs a working unsubscribe link and to say it's from Perth AI.
- A prize-draw email on its own is only for contacting the winner.

## One-off setup in Cloudflare

1. **The database** is created by the first deploy after this merges, the same way Wrangler already
   creates the `SESSION` KV namespace, and the table is created on first use. If that deploy fails
   on the D1 step, create it by hand and paste the id it prints into `wrangler.jsonc` as
   `database_id`:

   ```bash
   npx wrangler d1 create perth-ai-ddd-2026
   ```

2. **The admin PIN** is a secret, at least 12 characters (the admin page is on the public
   internet). Until it's set, admin says it's switched off. Stick to what the booth screen's own
   keyboard can type: letters, digits, space, and `! @ # $ % ^ & * ( ) ' - _ . , ?` (the symbols
   sit on Shift + the number row, like a physical keyboard). Set it in the dashboard (Workers &
   Pages → perth-ai-website → Settings → Variables and Secrets → add a Secret named
   `DDD_ADMIN_PIN`), or run:

   ```bash
   npx wrangler secret put DDD_ADMIN_PIN
   ```

## On the day

- **Booth devices open `perthai.org/ddd-2026/?booth`.** That turns on booth mode: after a quiet
  minute it wipes back to the home screen (so the next visitor never sees someone's details), the
  home screen turns into the self-playing game, and QR codes are for scanning rather than tapping,
  so nothing on the booth links out of the kiosk. It also keeps the screen from dimming. The device
  remembers it; `?booth=0` turns it off, and so does the switch in admin (handy on an iPad in Guided
  Access, where retyping the URL is a pain). The plain link, for phones, does none of that.
- **Set each device up while it's online,** and open every screen once (Meet Perth AI, AI Disrupt,
  Quokka Run, a form). That's when it stores its offline copy.
- **Booth screen (Windows touch screen):** open it full screen in Chrome's kiosk mode from a
  Command Prompt (Alt+F4 to exit). The separate profile makes the flags stick even if Chrome is
  already open; the other flags stop pinch-zoom and swipe-to-go-back, which would fight the
  swipeable cards. It gets the kiosk's own on-screen keyboard; iPads, the Samsung tablet and phones
  use their own.

  ```
  start chrome --kiosk --no-first-run --disable-pinch --overscroll-history-navigation=0 --user-data-dir="%TEMP%\perthai-kiosk" "https://perthai.org/ddd-2026/?booth"
  ```

- **iPads:** open the booth link in Safari, then Share → Add to Home Screen, and open it from there
  (no browser bars). Turn on Guided Access (Settings → Accessibility) so it stays on the kiosk, and
  set its display auto-lock to Never.
- **Samsung tablet:** open the booth link in Chrome, then ⋮ → Install app (or Add to Home screen →
  Install). It opens full screen from its icon, like an app. Pin it with Settings → Security → Pin
  windows (the exact menu varies by model).
- **Clear the leaderboard on the morning.** Students will have been practising, so before the booth
  opens go to admin → "Clear public leaderboard". Practice scores are hidden, not deleted, and stay
  in the CSV. From then on, scores from any device count.
- **Admin:** hold the bear badge on the kiosk home screen for 3 seconds, or go to
  perthai.org/ddd-2026/admin. From there you can hide a rude name, clear the public board, download
  the scores CSV and draw a random winner. "Hide" hides every run by that player: the same email,
  or the same name for runs saved without one.
- **Top score wins,** so look over the board before announcing a winner. The API checks scores are
  plausible, but anyone determined could post a fake one. Hide it if so. What they can't do is
  flood the board: the API refuses a score once a player has 100 runs, and the kiosk shows the
  visitor why. It also holds back once 120 runs have arrived in the last minute from anywhere; the
  kiosk just keeps those on the device and sends them a minute later. Neither should happen at the
  booth (a keen student gets to 30 or 40 runs in a day, and every device emptying a backlog at once
  stays under 120); if it does, it's a script.

## Testing locally

```bash
cp .dev.vars.example .dev.vars
```

```bash
npm run preview
```

Then open http://127.0.0.1:8787/ddd-2026/ (admin PIN: the one in `.dev.vars`). `npm run dev` serves
the pages but not the D1 database, so use `preview` for the leaderboard and admin. Deep links such
as `#about/3`, `#summit`, `#runner`, `#attract` and `#form/slack` open a screen directly (load the
page fresh; changing only the `#…` part doesn't switch screens). Sign-up forms send to the real
inbox, even locally. To try a wifi drop, stop the server: the kiosk keeps working from its copy,
and whatever you saved meanwhile arrives within a minute of starting it again.

The automated checks in `tests/rotation/` (layout, rotation, and wifi drop-outs) run in GitHub
Actions whenever the kiosk changes. To run them yourself:

```bash
npm i --no-save @playwright/test http-server
```

```bash
npx playwright install chromium
```

```bash
npx playwright test --config playwright.config.mjs
```

## After the event

1. Download the scores CSV from admin and sort out the prizes.
2. Delete the database, which holds the draw entrants' emails:

   ```bash
   npx wrangler d1 delete perth-ai-ddd-2026
   ```

3. Remove `public/ddd-2026/` **except `sw.js`**, `src/pages/ddd-2026/`, `src/lib/ddd2026.ts`,
   `src/data/ddd2026.json`, the `d1_databases` block in `wrangler.jsonc`, `.dev.vars.example`, the
   `/ddd-2026/*` rule in `public/_headers` (keep the `sw.js` one), this page, the note in
   `CLAUDE.md`, the `qrcode` and `@types/qrcode` packages, `tests/rotation/`,
   `playwright.config.mjs` and `.github/workflows/quokka-rotation.yml`. Delete the `DDD_ADMIN_PIN`
   secret too.
4. Replace `sw.js` with the lines below. Browsers keep an installed service worker even after its
   file is gone, so this one tells every device that had the kiosk to delete its copy and remove
   the service worker. Leave it for a month or so, then delete it and its `_headers` rule.

   ```js
   self.addEventListener('install', () => self.skipWaiting());
   self.addEventListener('activate', (event) => {
     event.waitUntil(
       caches.keys()
         .then((keys) => Promise.all(keys.filter((k) => k.startsWith('ddd2026-')).map((k) => caches.delete(k))))
         .then(() => self.registration.unregister())
     );
   });
   ```
